Project Support Request

A Support item in the header of the web client files requests about this Odoo, as tasks of the project flagged Develops This Odoo (project_ai_driven), and lists the open ones of the user.

  • The item counts the open requests the user is a UAT user of: tasks of that project in an unfolded stage. Its panel splits them into Bugs (task type Bug) and Others, five at a time with View more for the rest; a request opens on its task form. View Closed lists the user’s requests in folded stages.
  • New Ticket takes a title and a task type and creates the task in the first unfolded stage of the project, with the user as its UAT user, no assignee and no estimate. Every internal user files requests, with or without Project rights and whether or not they read the project: the task is created with superuser rights, in the user’s name.
  • Without an active project carrying the flag the item is hidden.
  • Only internal users file and list requests: for any other user, a portal user for one, the item’s routes name no project, list nothing and refuse to create a request.

The task key (key) is shown before the title where a module of the database declares it, such as OCA project_key.

Configuration

A Settings administrator ticks Develops This Odoo on the form of the AI-driven project that develops this database (project_ai_driven). Until an active project carries it, the Support item is hidden.

A request is created with a task type and no estimate in the first unfolded stage of that project: keep that stage out of Stages Requiring a Type and an Estimate (project_ai_driven), or the request is refused and the item answers Error creating ticket.

Usage

Press Support in the header:

  • switch between Bugs and Others, the requests you are a UAT user of, and press one to open its task;
  • New Ticket: type a title, pick a type and press Create; the new task opens;
  • View Closed lists your requests in folded stages.

Bug Tracker

Bugs are tracked on GitHub Issues. In case of trouble, please check there if your issue has already been reported. If you spotted it first, help us to smash it by providing a detailed and welcomed feedback.

Do not contact contributors directly about support or help with technical issues.
