Shows Odoo's own refresh notice, *The page appears to be out of date.* with
its **Refresh** button, in every open backend tab whose code is out of date
after a module update.

Odoo sends ``bundle_changed`` on the bus whenever it saves its tracked asset
bundle, ``web.assets_web``, but its web client shows the notice only when the
server version changes, which a module update never does. Tabs opened before
a deploy would keep running the old JavaScript, calling routes that may be
gone, until they are reloaded.

How a tab decides:

* The page carries its baseline: the files of ``web.assets_web`` and their
  versions, as the web client's asset URLs name them (Odoo versions the
  script and the stylesheet apart), in its session info
  (``bundle_versions``). The tab needs no request to start. A deploy that
  lands between the page's render and the tab's start is usually noticed
  too, as the bus replays to the tab what it sent after the render; a bus
  worker another tab started and shares may not, and the tab then compares
  at the next ``bundle_changed``.
* On ``bundle_changed`` with an unchanged server version, it waits 10 to 60
  seconds, the random spread of Odoo's own notice, asks
  ``/web_bundle_refresh_notice/versions`` for the same and compares: a file
  in another version, a new file or a gone file brings the notice. A
  further ``bundle_changed`` restarts the wait, so a burst of them brings
  one request. A failed request or an empty answer brings nothing, and the
  tab keeps its baseline for the next ``bundle_changed``.
* The page and the route give the same whatever the session's debug mode or
  website, so ``debug=assets`` tabs, dark mode tabs and the website editor
  are compared too. Both read the same cached link lists the web client
  page renders its asset tags from; a worker that has not cached them yet
  builds them first.
* The route skips the identity check, so a session awaiting one gets no lock
  dialog for it: its answer is asset checksums, which page URLs carry
  anyway.
* One notice at a time per tab; once it is closed, a later change shows it
  again. A change of server version is left to Odoo's own notice. The page
  is never reloaded without the user.

The notice runs wherever ``web.assets_backend`` is loaded, the same pages as
Odoo's own notice: the backend web client. The website, the portal, Point of
Sale and the subcontracting portal load other bundles and do not get it, nor
do tabs opened before the module was installed: a page without a baseline
leaves its tab quiet.

Usage
=====

After a deploy, an open backend tab still running the old code shows
*The page appears to be out of date.* 10 to 60 seconds after Odoo has
rebuilt its assets:

* press **Refresh** to reload the page on the new code;
* or close the notice, keep working and reload later. Until then the tab
  runs the old code, which may call routes the update removed.

Tabs opened after the deploy already run the new code and show nothing.

Known issues / Roadmap
======================

* A change that touches only a bundle Odoo does not track brings no notice:
  a dark mode stylesheet alone (``web.assets_web_dark``), for one.
* The website editor test runs only in a database with ``website``
  installed.
