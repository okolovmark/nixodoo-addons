Software-team additions to project tasks: task attributes, clarifying
questions with their answers and the technical solution, a checklist and test
cases per task.

**Task attributes** (``project.task``)

* **Priority** (Highest to Lowest), **T-shirt Estimate** (XS = 1h or less, S
  = 4h, M = 1d, L = 3d, XL = 1w, XXL = 2w or more), **Task Type** (Feature,
  Bug, Improvement, Investigation, Milestone, Support, Technical Debt),
  **Difficulty** and **Knowledge Area Level**, next to the tags on the task
  form. The type is also a column of the task list.
* Picking a T-shirt estimate fills *Initially Planned Hours* while it is
  empty: 1, 4, 8, 24, 40 or 80 hours. The value is kept only where that field
  is on the task form, which is the case once Timesheets is installed.
* A **Technical Solution** tab with Questions, Answers and Solution, shown to
  project users on the tasks of a project flagged **Software Project**.
* Assignment notifications honour the ``mail_auto_subscribe_no_notify``
  context, so an account without an email address (an RPC service account)
  can assign tasks without failing.

**Checklist** (``project.task.subtask``)

Task-level checklist items with a description, an **Assigned to** user, a
**Reviewer** (the creator), a deadline and a state: TODO, Waiting, Done,
Cancelled. Only the reviewer and the assignee may change an item's state or
description. Every creation, state, name or assignee change posts a message
to the task addressed to the reviewer and/or the assignee, under the internal
*All checklist updates* subtype (a change on an item whose reviewer and
assignee are both the current user is a plain note instead). The subtype is
not subscribed by default: other followers receive these posts only after
opting into *All checklist updates* on the task or on its project. The same
context key silences these posts for an account without an email address.
The task's kanban card shows the current user's completion percentage over
their non-cancelled items and the number of their TODO and Waiting items. The
**Checklist** menu opens on your own TODO items (the *My* and *TODO* filters
are on by default); remove those filters to see all items.

**Test cases** (``project.task.testcase``)

Ordered test cases per task with Steps to execute, Expected results,
Comments, a Passed flag and the same four states. The task carries a
**Tester**, general comments and a completion percentage over non-cancelled
cases. The **Test Cases** menu opens filtered on the cases still in *TODO*;
remove the *TODO* filter to see them all. Copying a task also copies its
checklist items and test cases, keeping their states.

**Coming from kaertech_project_software**

These features were cut from the module ``kaertech_project_software``. On a
database that has it installed, installing this module takes over the models,
fields, views, access rights, menus and message subtypes that already exist,
under their database ids, instead of creating new ones: existing checklist
items, test cases, field values and follower subscriptions stay as they are.
Nothing has to be done by hand.

Configuration
=============

* On a project, tick **Software Project** (*Settings* tab, above
  *Visibility*) to show the Technical Solution tab on its tasks.
* Checklist items and test cases are managed by **Project / User**. The
  Checklist, Test Cases and Technical Solution tabs are hidden from users
  without that group.
* To be notified of checklist items that are neither assigned to you nor
  created by you, edit your follower subscription on the task or on the
  project and tick *All checklist updates*.
* An integration that writes tasks or checklist items with an account that
  has no email address passes ``mail_auto_subscribe_no_notify`` in the
  context; without it Odoo refuses to send the notification and the write
  fails.

Usage
=====

On the task form:

* Set **Priority**, **T-shirt Estimate**, **Task Type**, **Difficulty** and
  **Knowledge Area Level** next to the tags.
* *Checklist* tab: add items, each with an **Assigned to** user and an
  optional deadline. The assignee or the reviewer moves an item with the
  state icons (TODO, Waiting, Done, Cancelled). The task's kanban card shows
  your own completion percentage, only when you have non-cancelled items
  assigned to you.
* *Test Cases* tab: add ordered cases with steps and expected results, set
  the **Tester**, then move each case with the state icons. Marking a case
  Done ticks **Passed**; any other state, Cancelled included, clears it.
* *Technical Solution* tab (software projects): record the Questions, the
  Answers and the Solution.

**Project > Checklist** lists the checklist items of all tasks, opened on
your own TODO items. **Project > Test Cases** lists the test cases of all
tasks, opened on the ones still in TODO.
